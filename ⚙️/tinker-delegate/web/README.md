# The Gate: Health — `web/`

An interactive, publication-style single-page app for **privacy-preserving, TEE-gated bio-model collaboration**. The through-line: the owner's health data never has to leave, and **no model touches a sensitive corpus until the request clears a pre-inference safeguards gate**.

This is the frontend for `tinker-delegate` (the NDAI Attested Diligence Room). The gate sits *before* the paper's bounded-evaluation step; the attestation records here map to real TDX quotes, the bounded results map to the backend's `ScoreBand` outputs, and `royaltyPerQuery` maps to the marketplace metering. Cleared, bounded results are delivered to a person's or org's inbox via **wikigen.me**.

> ⚠️ **Illustrative scaffolding.** Every corpus, principal, request, verdict, and attestation is synthetic and clearly non-real. There is **no real PHI, no real identifiers, and no real genomes** anywhere in this repo. The gate's verdict logic is a demonstration **to be replaced by real screening + human review in production**.

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck (tsc -b) + production build to dist/
npm run preview    # serve the built dist/
npm test           # run the pure-gate unit tests (vitest)
```

Requires Node 18+ (developed on Node 24). No backend is needed — the gate evaluator runs client-side as a pure function.

## What's in it

- **Deployment spine** — every app is tagged on one axis: *does your data have to leave?* `on-device` / `enclave` = stays local (teal); `hybrid` = caution (olive); `api-only` = data leaves (amber). Color is information and is always paired with a text label.
- **The gate** — the four ordered pre-inference checks, explained.
- **Gate simulator** — pick an example request, run it, and watch stages resolve `pass` / `hold` / `deny` to a terminal `CLEARED` / `STOPPED`. Includes a restricted-category request that deterministically denies at stage 3 and emits a stop-record.
- **Live data panel** — the current `AccessRequest`, `StageVerdict[]`, `AttestationRecord`, and `CorpusPolicy` as syntax-highlighted JSON, regenerated per run.
- **Catalog** — health & bio-model apps across all four localities, filterable by locality.
- **Capability registry** — the pipelines a `pipelineAllowlist` can point at, each tagged with locality + misuse-sensitivity. Includes bioinformatics **foundation bio models** (variant/splicing, protein structure & language models, single-cell/spatial/pathology, multi-omics, ADMET, metagenomics) as analysis-first capabilities — and generative/de-novo design as **restricted deny-targets**, never shippable tools. Filter by foundation-model / clinician-gated / restricted.
- **Scientific agent skills** — the tools an agent wields *inside* the gate (framing, data QC/harmonization, in-enclave analysis, orchestration/outsourcing, safety self-screening, delivery), each with its own gating profile and human-in-the-loop choke points.
- **Shared collaborative sessions** — N-party collaboration over multiple sealed corpora: each cross-corpus query is an independently-gated `AccessRequest`, the session accretes a corpus-tagged shared trace + a co-signed joint attestation, with unanimous consent, per-party royalty metering, revocation, and fail-closed handoff. See [`src/types-collab.ts`](src/types-collab.ts).
- **Restricted** — heritable/germline editing shown *only* as a gated-deny, with human-review routing. No methods anywhere.
- **Private-infra roadmap** — an honest shipped-vs-planned roadmap for the confidential-compute backend (TDX quote verification, per-corpus key sealing, ConSECA policy engine, egress/DLP, the HOLD reviewer queue, federated learning + DP, transparency log, royalty settlement), tied to the real files/contracts/papers. Candid that today's attestation signatures are illustrative, not cryptographically verified.
- **Live TEE** — the real counterpart to the illustrative attestations. A client ([`src/lib/dstackVerifier.ts`](src/lib/dstackVerifier.ts)) fetches a **genuine Intel TDX quote** from [amiller's dstack-webhost](https://amiller.github.io/dstack-webhost) tee-daemon running in a Phala CVM. Its verifier endpoints are public and `Access-Control-Allow-Origin: *`, so the SPA fetches a real attestation cross-origin with no token — binding source `tree_hash` → image digest → TDX quote → KMS-rooted key. A captured bundle ([`src/data/attestationFixture.ts`](src/data/attestationFixture.ts)) is the offline fallback. This is the concrete path to making this app's own “attested” real: its Vite `dist/` deploys as a `runtime:"static"` project and promotes to `attested`.
- **Safeguards** — the non-negotiables.

> The registry, agent-skills, infra-roadmap, and collaboration content was generated by a multi-agent design pass and then **adversarially safety-reviewed** against the non-negotiables (biosecurity + privacy): generative/de-novo bio design is restricted everywhere, dual-use capabilities are gated, and the bio-risk stage stays screen-and-deny.

## The pre-inference safeguards gate

Before any model runs against a sensitive corpus, a request passes four ordered checks. Each returns `pass` / `hold` (human review) / `deny`. **The run stops at the first non-pass.** Every run — cleared or stopped — emits a signed attestation.

1. **Identity & authorization** — attested identity; KYC-style vetting; optional biometric/facial verification for high-assurance tiers (opt-in, proportionate, privacy-law-bound — never default-on).
2. **Purpose & use-case screening** — declared purpose matched against the corpus's allowed-use policy and pipeline allowlist; dual-use / improper intent flagged.
3. **Bio-risk / clinical-safety screening** — request screened against restricted categories before inference. **Screen-and-deny only**: no operational detail, no methods.
4. **Attested execution** — only cleared requests reach the enclave; a bounded result is returned, raw values never surfaced; provenance is emitted.

The gate is a **pure function** of `(AccessRequest, CorpusPolicy)` — see [`src/gate/evaluate.ts`](src/gate/evaluate.ts) (`evaluateGate`). Purity keeps it testable and auditable; the impure sealing (uuid / clock / signature) is injected via `runGate(request, policy, env)`. Tests live in [`src/gate/evaluate.test.ts`](src/gate/evaluate.test.ts).

## Data contracts

Defined in [`src/types.ts`](src/types.ts). The UI is built against these shapes.

```ts
type AccessRequest = {
  requestId: string;              // uuid, regenerated per run
  requester: IdentityRef;         // verified principal + role
  assuranceTier: 'standard' | 'elevated';   // elevated => biometric/facial
  corpusRef: string;              // pointer to sealed corpus; never raw data
  pipelineRef: string;            // which registry capability is requested
  declaredPurpose: string;
  intent: string;                 // free-text intent, screened at stage 2/3
  justification?: JustificationRef; // IRB / clinician order / consent evidence
};

type StageVerdict = {
  stage: 1 | 2 | 3 | 4;
  decision: 'pass' | 'hold' | 'deny';
  reason: string;
  signals: Record<string, number>;
  reviewer: IdentityRef | null;   // set when a hold is resolved by a human
  at: string;                     // iso-8601
};

type AttestationRecord = {
  attestationId: string;
  outcome: 'cleared' | 'stopped';
  requestId: string;
  who: IdentityRef;
  where: EnclaveRef | 'gate://pre-inference';
  corpusRef: string;
  pipelineRef: string;
  gateTrace: Pick<StageVerdict, 'stage' | 'decision'>[];
  resultHash: string | null;      // hash only; raw output never stored
  boundedResult: BoundedResult | null; // coarse, non-raw signal only
  signature: string;              // enclave-signed, tamper-evident
  at: string;
  routedTo?: string;              // where a stopped run was escalated
};

type CorpusPolicy = {
  corpusRef: string;
  label: string;
  sensitivityTier: 'low' | 'med' | 'high' | 'restricted';
  requiredAssurance: 'standard' | 'elevated';
  allowedPurposes: string[];
  pipelineAllowlist: string[];
  restrictedCategories: string[]; // e.g. 'heritable-germline-editing'
  royaltyPerQuery: number;        // marketplace metering for the expose path
  custodian: string;
};
```

## Non-negotiables (honored exactly)

1. **No germline / heritable editing content beyond the gated-deny demo.** No protocol, method, target, reagent, or workflow anywhere — only a restricted category the gate blocks.
2. **No clinical instructions.** Health apps are decision-support and education, with "not a diagnosis / consult a clinician" framing and crisis-resource signposting on mental-health surfaces.
3. **No dangerous bio-uplift.** The bio-risk stage is described only at the level of "screen and deny."
4. **Biometric/facial verification is opt-in**, proportionate, and privacy-law-bound — never default surveillance.
5. **Synthetic data only.**
6. **The gate is an auditable pure function**; every run emits an attestation, including denials.

## Accessibility

Semantic HTML, keyboard-navigable (the live-data tabs implement the WAI-ARIA tabs pattern with arrow-key roving; the scenario picker uses a native radiogroup), visible focus rings, `prefers-reduced-motion` honored (the stage reveal becomes instant), no essential information conveyed by color alone (every color is paired with a text label), responsive down to ~380px.
